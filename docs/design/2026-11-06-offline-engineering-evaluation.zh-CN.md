# 离线工程评测

[English](2026-11-06-offline-engineering-evaluation.md) | [简体中文](2026-11-06-offline-engineering-evaluation.zh-CN.md)

## 目的与现状

工程版需要可重复的比较方式，并且应将用量统计与工程质量分开。仓库已有启动和集成基准测试，但没有用于编码任务结果和提供方用量的离线报告格式。本设计增加本地比较器、一个使用本地模拟提供方的 CLI 冒烟任务，以及一个确定性的十类任务基准测试；不会调用已配置的模型。

## 目标与边界

- 比较十类工程任务中相互匹配的基线和候选记录。
- 将 token、请求、重试、工具、子代理、压缩和提供方报告的成本，与任务完成、测试、回归缺陷和人工审查结果分开报告。
- 未知成本继续保持未知，并明确标记合成夹具。
- 拒绝格式错误或无法匹配的运行记录。
- 不添加依赖、凭据或线上端点，也不根据 token 数量推断质量。

这是针对已记录或模拟用量的比较工具，不是代理运行器、成本估算器或自动代码质量评审器。

## 方案

1. 将评测逻辑加入生产环境的 core telemetry 服务。这会让测试报告与运行时代码耦合，并不必要地扩大 core 改动范围。
2. 创建独立的离线比较器和带版本的夹具格式。选择此方案，因为它能隔离基准测试工具，并在不联网的情况下验证提供方用量。
3. 在基准测试运行器中调用真实模型端点。这需要凭据且会消耗配额，因此不属于本地实现范围。

## 设计

`evaluation/cases.json` 定义稳定的用例标识符。`evaluation/compare.mjs` 验证带版本的 JSON 运行集，要求提供方、模型、协议、配置指纹和用例/样本配对一致，汇总提供方指标，并且仅在基线数值已知且非零时计算百分比变化。只有输入中的成本全部来自提供方报告时，才汇总成本。质量结果作为独立的基线/候选摘要报告。命令将 JSON 写入标准输出，或在不覆盖已有文件的情况下创建输出文件。

未报告的 usage 字段在汇总后仍为 `null`，不会被当成零。

合成夹具覆盖全部十类用例，用于验证格式。其数值明确不代表实测结果。未来的实测比较必须保证双方使用相同的用例、样本、提供方/模型配置和任务条件；在接受质量结论前，人工评审者必须检查代码。

`integration-tests/engineering-evaluation.test.ts` 另外通过打包后的 CLI 和现有的本机 OpenAI 兼容模拟服务器运行一个固定的文件写入任务。它会检查文件内容和模拟提供方的已知用量。如果 `QWEN_EVALUATION_BASELINE_CLI` 指向单独构建的基线 CLI，则同一任务也会在基线和候选版本上运行。已在上游 `21ed8f1efbb351b973d96e2bc9efa78f278df99c` 和当前分支上验证：两者均通过，并使用相同的模拟响应和用量。设置 `QWEN_EVALUATION_RUNS_DIR` 后，测试还会写出 schema-v1 合成运行记录；未观测到的字段保持为 `null`。此冒烟测试不会测量实测节省，也不代表广泛的工程质量评估。

`integration-tests/engineering-benchmark.test.ts` 通过打包后的 CLI 和同一本地模拟服务器，在十类任务中各运行一个确定性任务。每个用例都将任务完成、测试结果和回归缺陷与 token 用量分开检查。长会话用例通过缩小上下文窗口强制触发压缩，恢复用例则记录会话并使用 `--continue` 继续执行。可选的基线 CLI 和运行记录保存使用与冒烟任务相同的环境变量。

## 验证与验收

- Node 内置测试运行器覆盖汇总、零基线、错误标识符、实验配置不匹配，以及未知的用量/成本字段。
- 已提交的合成比较可离线运行，且不会报告实测节省。
- 单用例模拟提供方 CLI 冒烟任务无需外网即可运行，并验证文件变更和模拟用量总数。
- 可选的基线 CLI 可使用相同任务和模拟响应进行测试；固定用量值按设计相同。
- 十类任务基准测试在基线和候选 CLI 上均通过，并离线验证每个任务的完成情况和测试结果。
- 不会联系模型端点或外部服务。
- 文档说明数据格式及其限制。

## 限制

比较器本身不会启动代理、捕获用量、执行测试、标准化特定模型的价目表，也不会对人工审查的代码质量评分。冒烟测试仅覆盖一个确定性任务。十类任务基准测试证明执行路径和格式兼容性，但双方接收相同的脚本化响应，因此不能衡量节省。经过真实人工评审的质量测量以及任何经授权的线上比较仍待完成。
