# 会话级提供方令牌配额

[English version](2026-11-06-session-provider-quota.md)

## 背景

主请求之后，工作流可能会调度可选的辅助 Agent 请求。现有工作流令牌预算
只统计输出令牌，不统计提供方报告的总用量（包括缓存输入）。API 响应遥测
已规范化提供方用量，但会话遥测没有记录每个响应是否都提供了精确总量。

## 决策

在 `UiTelemetryService` 中增加会话级精确总量计数器。只累加提供方报告的正数
`total_token_count`。任何成功响应未报告总量或报告非正数总量时，会话总量变为
未知，直到重置前都保持未知。仅从历史模型汇总恢复时无法重建逐响应的提供方
总量，因此标为未知。回放回滚快照会保留精确或未知状态。
会话关闭后也标为未知，避免仍在运行的可选工作流将已清除的遥测误认为尚未使用配额。

增加可选配置 `QWEN_CODE_MAX_PROVIDER_TOKENS_PER_SESSION`。配置后，达到或超过
上限时，工作流宿主拒绝新的可选工作流 Agent 调度，`Agent` 工具拒绝新的可选
子代理生成；会话用量未知时两者都拒绝。达到上限的 80% 后仅警告一次。工作流
宿主在调度入口和执行槽位获取时都会检查。不会中断正在执行的请求，也不会中断
主模型响应。现有工作流输出令牌上限保持独立。

## 消费方和边界

共享的配额解析和错误文案位于 `telemetry/provider-quota.ts`。新的遥测读取接口
由 `WorkflowBudgetImpl.fromConfig` 和 `Agent` 工具的子代理准入检查使用。宿主侧
配额状态由 `workflow-orchestrator.ts` 的两个门控点检查，不会暴露给工作流
JavaScript。现有遥测回放消费方继续使用相同的快照事务。

## 限制

此配额按会话统计，不是费用上限，也不是单轮上限。启用上限后，未报告总量或报告
非正数总量的提供方会导致可选工作流调度和 `Agent` 子代理生成被拒绝。该门控
无法限制已运行的请求或主请求；并行执行的辅助 Agent 可能在响应记录前越过上限。

## 验证

增加聚合、未知用量、重置和移除、回放回滚、配置解析、警告行为、两个工作流
调度门控以及 `Agent` 子代理准入的测试。运行遥测、工作流预算/编排和 Agent 的
定向测试，然后构建并进行类型检查。
