# Engineering Edition Roadmap

Milestones are sequential. A milestone is complete only when its stated checks pass and `IMPLEMENTATION-STATUS.md` records evidence.

| Milestone                    | Scope                                                                                                                                           | Acceptance                                                                                                                                                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 0. Foundation                | Record actual fork revision, clean/dirty state, fork workflow risks, and available build prerequisites.                                         | Baseline is explicit; no user changes overwritten; no fork workflow enabled.                                                                                                                                                         |
| 1. Usage observability       | Audit provider usage fields and aggregation paths; add only missing reporting.                                                                  | Unit tests cover provider omissions, cache fields, reasoning convention, and aggregation without double counting.                                                                                                                    |
| 2. Engineering quality       | Audit prompts and skill activation; add compact, on-demand engineering guidance where a concrete gap exists.                                    | Complete: six path-activated bundled skills added without entering the always-loaded index; activation and prompting tests pass with no duplicate always-on instructions.                                                            |
| 3. Context                   | Audit compression/retention against restoration requirements.                                                                                   | Regression fixtures preserve constraints, decisions, errors, evidence, and source references; measured before/after fixture size.                                                                                                    |
| 4. Tools                     | Audit schema deferral, diagnostics, recovery, and LSP navigation.                                                                               | Required tools remain reachable; recovered output and nonzero exit status remain explicit.                                                                                                                                           |
| 5. Quota                     | Extend existing budget/usage mechanisms only if they can gate optional requests safely.                                                         | Implemented: exact-or-unknown session provider totals; 80% warning; hard refusal of optional workflow agent dispatches at both admission gates and optional Agent spawns; active requests and primary response remain uninterrupted. |
| 6. Providers                 | Validate existing protocol/capability translation with offline mocks.                                                                           | Tests cover supported providers and absent capability metadata; no live endpoint calls.                                                                                                                                              |
| 7. Evaluation                | Compare deterministic recorded/synthetic fixtures offline before any live comparison.                                                           | Complete offline: validated record comparison and a ten-category fake-provider benchmark that passes for both baseline and fork CLIs. Pending: human-reviewed quality results and any authorized live comparison.                    |
| 8. Terminal Polish & Release | Redesign terminal ASCII logo with balanced geometry, harden auxiliary quota gates, author human evaluation rubric, build executable CLI binary. | Complete: faithful symmetrical 28w/20w half-block logo and 100w source of truth preserved; auxiliary inference gates in session title and tool summary; 8-dimension human review rubric; `./bin/qwen-code` binary and bundle ready.  |

Each production change should remain independently reviewable and pass relevant package checks. Full live-model evaluation is out of scope without explicit authorization.
